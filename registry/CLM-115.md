# CLM-115 — E43 Exact Frozen Representation Exceeds the Per-Case Runtime Cap
# CLM-115 — E43 고정 표현은 Case별 Runtime Cap을 초과함

## Verified claim / 검증 주장

Under the exact preregistered E43 representation on a standard public GitHub Ubuntu runner:
- checksum-frozen NIST source integrity passed;
- exact F42 N0/R1 input hashes were reproduced;
- pinned 3DThesis build passed;
- N0 execution reached the frozen `480 s` per-case cap and terminated with return code `124`;
- R1 was not executed after N0 runtime failure, per fail-closed workflow logic.

Therefore E43 final gate is **`HOLD_E43_RUNTIME_OR_INTEGRITY`**.

## Claim boundary / 주장 경계

This result establishes **runtime infeasibility of the exact E43 computational representation under the frozen zero-cost cap**. It does **not** establish that path ordering has no thermal effect, that R1 is better/worse than N0, or that the F41/F42 source-grounded path-order hypothesis is rejected.

No E43 `MP_width` performance comparison is available.
