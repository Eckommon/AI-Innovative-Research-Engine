# CLM-118 — Korean Port-Call Identity Is Metadata-Supported but Record Validation Is Pending
# CLM-118 — 한국 Port-Call 식별자는 Metadata 수준에서 지지되나 Record 검증은 보류

## Claim / 주장

Official Korean public-data metadata supports the candidate event identity:

`(port/port-authority identifier, arrival year, arrival count, call sign)`

as a defensible port-call key across vessel entry/exit and facility-use surfaces at the **metadata/schema level**.

Official vessel-entry/exit metadata also supports arrival and departure timestamps within the same record family, making `departure - arrival` a defensible **port-stay / vessel-turnaround proxy candidate**.

## Evidence / 근거

- Ministry of Oceans and Fisheries vessel entry/exit surfaces expose port, call sign, arrival count and arrival/departure timestamps.
- `3056955 항만시설사용정보` requires `prtAgCd + etryptYear + etryptCo + clsgn` and returns the same fields.
- Its official documentation sample allows multiple rows under one call key, so facility rows are nested/contextual rather than independent calls.
- `unityFrghtUpdtOdr` exposes correction-sequence semantics at schema level.
- Current `15160015 시설사용허가현황` adds requested/designated facility periods and authorization status.
- KMA ASOS hourly observations plus station-coordinate history and an official port-location layer provide a defensible weather-join route.

## Boundary / 경계

Not yet validated:
- record-level uniqueness of the four-part key;
- deterministic correction/latest-record handling;
- missing/zero/negative duration rates;
- exact PORT-MIS timestamp timezone normalization;
- berth-waiting, anchorage-waiting, cargo-handling or causal congestion constructs.

Therefore this claim does not authorize predictive modeling and does not elevate `port_stay_hours` to a congestion-delay metric.
