# DEC-092 — Finalize F45 HOLD; Authorize Persistent Partial-File Resume Ingress Gate
# DEC-092 — F45 HOLD 종결 및 Persistent Partial-File Resume Ingress Gate 승인

## Decision / 결정

Finalize F45 as **`HOLD_F45_SOURCE_OR_NETWORK`**. Do not increase F45 range timeout/retries, adapt chunk size, or reinterpret it as range-protocol rejection.

Authorize a separately numbered source-only gate **AMBENCH-F46 — Persistent Partial-File Resume Ingress Qualification**.

## Why a new protocol / 새 protocol 이유

F44 whole-object reads sometimes transferred multi-megabyte prefixes before failing, while F45's explicit first 1 MiB range never completed under its frozen read cap. A distinct fixed strategy is therefore justified: preserve any partial whole-object file on disk and use curl's documented `--continue-at -` behavior on the next attempt, rather than discarding a failed prefix or pre-splitting the source into ranges.

Curl documentation states that `--continue-at -` determines the resume offset from the output file. F46 will use an explicit outer attempt loop so a failed partial output is intentionally retained between attempts; it will not rely on curl's built-in retry behavior that may reset output data.

## F46 authorization boundary / F46 승인 경계

F46 must remain source-only and prospectively fixed before execution:
- same official NIST NERDm component and expected size/SHA;
- same exact NERDm `downloadURL` only;
- one persistent local partial file;
- fixed curl resume command semantics;
- fixed attempts/time caps and fail-closed gates;
- exact final size/SHA and ZIP/P01 identity required;
- no simulator, MP_Stats, representation or path-order analysis;
- no mirror/proxy/VPN/paid storage;
- no raw archive persistence.

A PASS may support a separate minimal-source-fixture decision, but does not reopen F44 or establish representation equivalence.

## Cost / 비용

Incremental monetary cost remains `0 USD`. No billable service is authorized.
