The archive is only required by the **current exact P01/3DThesis descendant route** because that route reconstructs the source-native P01 command geometry from `RHF_Command/RHF_P01_layer0001.csv`. The scientific content required is the P01 command information, not the ZIP container itself.

It is **not required** for:
- the overall innovation-discovery engine;
- Wave 2/3 geographic expansion;
- cross-dataset/cross-agency/cross-national research;
- the already validated E29/E33/E36 mechanism-convergence evidence;
- the F37 multi-actuator research hypothesis as a general engineering question;

The archive is therefore a **route dependency**, not a **mission dependency**.

## 4. Finding C — recent work has drifted from innovation discovery toward research-infrastructure debugging / 최근 작업은 혁신탐색보다 연구 인프라 디버깅 쪽으로 편향됨

By contrast, the recent queue became increasingly serial inside one NIST additive-manufacturing branch:

`E29/E33/E36 mechanism evidence → F37 synthesis → F38 novelty → F39 design → E40 input falsification → F41/F42 source-grounded simulator transfer → E43 runtime HOLD → F44 representation gate → F45 source-ingress gate → proposed F46 transport qualification`.

At E43–F45, the dominant blocker is no longer a scientific unknown. It is runner/runtime/source-transfer behavior. Continuing to create new numbered research gates solely to solve transport of the same archive risks **infrastructure recursion**: the experiment-support mechanism becomes the object of research.

## 5. Finding D — missing portfolio-level stopping rule / 포트폴리오 수준 중단 규칙 부재

Current governance has strong **within-experiment anti-rescue rules**, but it does not sufficiently constrain **cross-gate persistence** on one branch.

A branch can correctly stop E43, then open F44, F45, F46, etc. without violating any individual gate even when the marginal mission value is falling.

Recommended missing control:

### `MISSION-ROI / BRANCH-STOP` review
Before opening another descendant after repeated HOLD/REJECT:
1. Does the next gate resolve a scientific uncertainty or only an execution/tooling uncertainty?
2. Is the blocked source uniquely necessary to the project-level hypothesis?
3. Is there a higher-IPS independent candidate available?
4. Has the branch consumed >=2 consecutive infrastructure/runtime gates without new scientific evidence?
5. Would archiving the branch lose a unique claim, or merely defer one test?

If the answer is primarily tooling and an alternative candidate exists, default to `ARCHIVE/HOLD_BRANCH` and return to portfolio discovery.

## 6. Finding E — transient raw-data policy created repeated ingress dependence / transient raw-data 운영의 부작용

The project repeatedly kept large/raw NIST bytes transient while persisting hashes, schemas, derived metrics and claims. This minimizes repository size and raw-data retention, but it creates a structural consequence: later descendants must reacquire the same authoritative bytes.

For stable small licensed source members that are repeatedly reused, a future policy may consider a **provenance-bound minimal fixture** or another immutable reusable source representation. This must be governed separately; it should not be improvised as a rescue of the current experiment.

## 7. How research has actually been conducted / 실제 연구 진행 방식

The operational pattern has been:

1. **Read/reconcile GitHub SoT** — README/STATUS/HANDOFF/Issue/claim/decision.
2. **Source qualification** — official source, version, component identity, checksum, license, schema.
3. **Semantic qualification** — independent unit, nested measurements, joins, physical meaning, exposure/blindness state.
4. **Preregistration** — endpoint, baseline, aggregation, statistic, seed, materiality threshold, PASS/PARTIAL/REJECT/HOLD rules frozen before outcome access.
5. **Outcome-blind preflight** — schema/design/input identifiability first.
6. **Controlled execution** — standard public GitHub runner, zero incremental cost, raw files transient where practical.
7. **Fail-closed evaluation** — no post-hoc endpoint/model/threshold rescue inside the same experiment.
8. **Claim/decision persistence** — RESULT, CLM, DEC, Issue closure, STATUS/HANDOFF synchronization.
9. **Descendant gate creation** — if a scientific or source blocker remains, open a separately numbered gate rather than silently modify the parent.

This process is scientifically conservative and highly auditable, but the descendant-gate mechanism has recently become too permissive at the **portfolio level**.
